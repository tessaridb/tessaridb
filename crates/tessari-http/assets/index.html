Follow a table

from is a position in the log rather than a moment in time, so 0 replays everything the log still holds. Leave the table empty to follow every table you may read. A split table resumes from its cursor.

    Series

    A series ordered by its time field keeps each event where it happened; one ordered by arrival keeps it where it was written. A rollup is kept by the writes to its series.

    Spaces

    A space keeps one value per key. A plain write clears the key's expiry; a lock's value names its holder until its lease runs out.

    What is here, and what is not
    
              
    
              
    What the pane above shows is what this node itself knows: its own roles, the peers it has been told about, and the addresses it answers on. It is read from the node, not from anything standing beside it.
    
              
    
                How membership works
                
    Membership is a record and not a control plane: a node learns its peers through the same log it replicates data with, so there is nothing to stand up beside the database. A namespace declares how many copies the cluster keeps, and a peer's subscription decides which of them it receives. A leader holds a renewable lease granted by a majority and stops writing before that lease expires, measured on elapsed time rather than on the clock. A read may name the staleness it will accept, and a bound tighter than the cluster can know about itself is refused with the floor named. A write sent to a node that may not take it is forwarded to the one that may; one into a range another node leads, and a read only another node can answer, come back as a redirect carrying the client address, the node and the epoch it was decided under. A divergence is refused at the first divergent record and counted, never silently ranked.
    
              
    
              
    A split table's shards and placements change while it serves. Each change is a statement, and the store's leader can make some itself.
    
              
    
                Which statements change them
                
    ALTER TABLE … SPLIT AT and MERGE SHARD change the map in place, and SPLIT AUTOMATICALLY lets the store's leader do it by size and load. IDENTITY uuid SPREAD spreads new records over the shards, PARTITION BY gives each region its shard. ALTER REPLICA … LEADS moves a placement, LEADS NONE gives a range back to the store line, PREFERRED names the candidate that should lead it, and DEFINE FAILOVER … BALANCE LEADERSHIPS evens out who leads what.
    
              
    
              
    Lag is per follower, and leadership is what the log recorded.
    
              
    
                What the two figures are, and are not
                
    A follower's lag is how many records it is short of this node's tail, as this node last served it — the leader pushes each commit, so a level follower reads 0. A leadership is the row the winner wrote under its own epoch, so it says which node led a range as of that epoch; whether that node is alive now is its lease, which only it can report.
